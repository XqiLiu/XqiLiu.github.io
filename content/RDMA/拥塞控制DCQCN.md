# 基本概念
这里有几个基本概念可以简单介绍一下
## PFC
PFC的全称是**Priority-based Flow Control**，即基于优先级的流量控制。
对比一下子**传统以太网**和**PFC**的区别：
1. **为什么需要PFC**
	传统的TCP/IP在网络拥堵时，处理方式就是简单的**丢包**
	- **没有PFC时**：交换机缓冲区（Buffer）满了，新来的数据包直接丢弃。TCP 协议检测到丢包后会重传，这对普通业务没问题，但对高性能计算（RDMA）来说是灾难性的，会导致巨大的延迟。
	- **有了 PFC 后**：交换机缓冲区快满时，会发信号给上游，让上游暂缓发送。这样就用暂停代替了丢包，实现了**无损网络**。

2. **PFC改进了什么**
	在PFC之前，有一个老标准**IEEE 802.3x PAUSE**，但它有一个致命缺陷。
	- 传统 PAUSE（粗粒度）实现的时整条链路暂停
	- PFC改进了细粒度，利用以太网帧头的VLAN优先级，把一两条物理线路逻辑上分为了8个虚拟通道。

3. **PFC的副作用**
	虽然PFC解决了丢包问题，但是仍然存在问题，这个就是为什么又再次引进PFC的原因：
	- 拥塞扩散：如果接收端处理不过来，一直喊暂停，这个暂停命令会一级一级向上传导，甚至导致整个数据中心网络瘫痪（**PFC Storm**）
	- 不公平 (Unfairness)：一个流堵车出发了PFC，同一交换机节点的其它无辜流（Victim Flow）也会被迫阻塞。
## 交换机RED
RED的全称是**Random Early Detection**，即随机早期检测。
在交换机和路由器中，它是一种**主动队列管理（Active Queue Management, AQM**算法。
可以把它看作是交换机的一种**预警机制**，在DCQCN语境下，RED的作用就不再是丢包，而是打标记（ECN Marking）

1. RED的作用
	如果没有RED，交换机的默认行为时**尾部丢弃**
	- **机制**：只有当缓冲区完全填满时，交换机才开始丢弃新进来的包。
	- **后果**：这会导致**TCP全局同步**。也就是：完了过满负荷运行，直到塞满后，多个流同时丢包，所有流同时触发超时重传并降低速度，网络利用率跌入谷底，形成锯齿状的剧烈波动。
2. RED的工作机制
	RED试图在缓冲区填满之前就介入，以平滑流量。它不会等待100%使用才行动，而是根据平均队列长度来决策。
	![](DCQCN-f5.png)
	集合论文本身，RED主要由三个参数控制：
	- $K_{min}$（最小阈值）
		- 当队列长度小于$K_{min}$时，交换机认为网络空间很闲，**不做任何处理**
	- $K_{max}$（最大阈值）
		- 当队列长度超过$K_{max}$时，交换机认为完了过已经机器拥堵，**对所有包处理**
	
	- $P_{max}$（最大阈值）
		- 当队列长度处于 $K_{min}$ 和 $K_{max}$ 之间时，交换机会**线性增加**处理概率，从 0 增加到 $P_{max}$
## QCN
**QCN** 的全称是 **Quantized Congestion Notification**（量化拥塞通知）。
它是 IEEE **802.1Qau** 标准定义的一种**二层 Layer2**拥塞控制协议。
1. **核心机制**
QCN 是一种纯硬件的以太网拥塞控制机制，设计初衷是在同一个局域网（L2 Domain）内控制流速。

- “量化” (Quantized) 的含义：
    这是 QCN 最特别的地方。
    - **普通的 ECN（如 DCTCP）**：是**二元**的。交换机只告诉发送端“堵了”或者“没堵”。
    - **QCN**：是**量化**的。交换机会计算具体的拥塞程度（$F_b$ 值），直接告诉发送端：“现在堵了 30%，请降速 30%”或者“堵了 80%，请降速 80%”。这是一种非常精确的负反馈。
- 完全硬件实现：
    QCN 的逻辑（降速、通过计时器和字节计数器恢复速度）全部运行在网卡硬件上，不占用 CPU。
2. **DCQCN 从 QCN 继承了什么？**
	- 状态机（Figure 7）：Fast Recovery, Additive Increase, Hyper Increase），**全部是原封不动从 QCN 借鉴来的**。
	- **双重恢复机制**：利用 **Timer（计时器）** 和 **Byte Counter（字节计数器）** 来决定何时提升速度，这也是 QCN 的核心发明。
3. **QCN的缺陷**
	- **IP 路由问题（L3 网络）**： 现代数据中心网络（如微软的 Azure）是基于 **IP 路由（Layer 3）** 的。数据包每经过一个路由器（交换机），源 MAC 地址和目的 MAC 地址都会被修改（这是 IP 路由的基本原理）
	- **找不到源IP**： QCN 依赖 MAC 地址来识别流。如果网络深处的某个交换机发生了拥塞，它想发 QCN 反馈消息给源头，但它只看得到上一跳路由器的 MAC 地址，**根本不知道原始的发送端 IP 是谁**
	- **硬件修改太难**： 要把 QCN 改造成支持 IP 路由，需要修改交换机芯片（ASIC）。
# 算法设计
算法由三个实体组成：
1. CP（Congestion Point， 交换机）：这里没有使用 QCN 复杂的反馈机制，而是利用了现成交换机都支持的 ECN，降低了部署难度
2. NP（Notification Point， 接收端NIC）：当收到带有 ECN 标记的包时，接收端网卡会生成 **CNP (Congestion Notification Packet)** 发回给发送端。为了防止反向流量风暴，每 $N$ 微秒（论文中为 $50\mu s$）最多只发送一个 CNP
3. RP（Reaction point， 发送端NIC）：这是核心的控制逻辑。可以分为两个部分：降速部分、升速部分
	1. 降速过程：
		当收到 CNP 后，根据当前的速率$R_C$和因子$\alpha$降低发送速率 ，同时再更新target rate 和alpha值
		$R_T = R_C$
		$R_C = R_C(1-\alpha/2)$
		$\alpha = (1-g)\alpha + g$
	2. 升速过程
		如果没有收到拥塞信号，通过计时器（Timer）和字节计数器（ByteCounter）双重机制来恢复速率。这一部分需要稍微讲解一下：
		![](DCQCN.png)
		- 在Timer每过一段时间没拥塞，就尝试提速，方法是计数器$T+1$
		- 在流量维度上，每发送一定量的数据，如果没有接收到拥塞信号，就尝试提速。每触发依次，计数器$BC+1$
		只要一收到CNP，两个计数器立刻被重置为0
		所以这两个变量其实是在回答“已经平稳无拥塞多久”
		这里论文中提出了三种恢复手段，按照**激进程度**排序：
		**第一阶段：快速恢复 (Fast Recovery)**
		-  当 $T$ 和 $BC$ 都非常小的时候（$\max(T, BC) < F$），这个时候意味着刚收到CNP降速，开始慢慢恢复。
		- 此时采用**非常快**的恢复速度。他不盲目探测新带宽，而是试图快速回到降速前的目标速率$R_T$:$R_C = (R_T + R_C) / 2$
		**第二阶段：加性增长 (Additive Increase)**
		- 介于两者之间，此时已经恢复了一会，不再是刚拥塞完的状态
		- 此时采用**最慢最稳**的恢复方法，即传统TCP拥塞避免思路，小心翼翼地试探，每次只增加一点点固定速率$R_T = R_T + R_{AI}$ ，目标是保持稳定的前提下，慢慢寻找瓶颈带宽。
		**第三阶段：超级增长 (Hyper Increase)**
		- 当 $T$ 和 $BC$ 都很大（$\min(T, BC) > F$）时，这个时候即发了很多数据，又过了很长时间，都没有拥塞。
		- 此时速度采用**极其激进**地方法，大幅提升目标速率，以便快速占满空闲带宽（这继承自 QCN 的逻辑）。
		
		

# 疑惑讨论
1. 为什么尺子（$T$ 和 $BC$ 值大小）中等是恢复最慢的，而不是尺子短的时候？
	 这一直觉想法是对的，例如TCP慢启动逻辑，但 **DCQCN 的设计逻辑恰恰相反**，这是因为它有一个 TCP 没有的关键概念：**目标速率 ($R_T$, Target Rate)**。
	1. 为什么尺子短的时候要**快速回复**？
		1. **DCQCN 的逻辑：** 刚才撞车是因为**稍微**超速了一点点，但我知道这条路其实能跑得很快，不需要从零开始慢慢蹭。
		2. 当收到拥塞信号 (CNP)，DCQCN 会把当前速率 ($R_C$) 砍得很狠（比如砍掉一半），但它会**记住**刚才那个导致拥塞的高速率，把它存为 **目标速率 ($R_T$)**，它的任务不是去探索未知的领域，而是**填补**因为刚才“急刹车”而空出来的带宽。
	2. 为什么尺子中等的时候要**最慢**？
		1. **DCQCN 的逻辑：** 我们已经回到了悬崖边缘，再快一点点就会掉下去（再次拥塞）
		2. 经过了 Fast Recovery，现在的速度 $R_C$ 已经非常接近 $R_T$（也就是网络的物理极限）。它的任务是**小心试探**。这里的每一步只增加固定的 $R_{AI}$（通常是 40Mbps 这样很小的值）。因为此时网络几乎是满载的，任何大幅度的加速都会立刻触发拥塞
	3. 为什么尺子长，还需要**冲刺（Hyper Increase）**？
		1. DCQCN 的逻辑：** Fast Recovery 只能回到“过去的高水平”，它无法发现“**新出现的巨大空闲**”。
		2. 当 $T$ 和 $BC$ 很大，这暗示着**外部环境变了**（可能有别的流退出了，空出了巨大带宽）。这时候必须**冲刺**，大幅提升目标速率 $R_T$，去抢占那部分新空出来的带宽。
